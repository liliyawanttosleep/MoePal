# 开发日志（中文）

## 2026-11-21 · v0.5 三维转身、有情绪的声音、三支角色 PV

用户反馈：小人是平面的，转身 / 侧面没有立体感；动作要更顺；声音僵硬、要自然有情绪、更甜；
登场动画要用流畅的三维模型；每个角色做一支约 5 分钟的专属 PV。

### 1. 三维模型与 360° 转身
- `tools/make_3d.py`（环境 `.conda-3d`：Python 3.10 + PyTorch 2.7.1 cu128）：Hunyuan3D-2mv（腾讯开源，用正面 / 侧面 / 背面三张图一起生成形状）
  从 `assets/<角色>/view_*.png` 生成网格（约 10 万顶点 / 20 万面，RTX 5070 Ti 每个约 3.3 分钟）。输入先去掉脚下浅灰阴影，否则会多出一块“地板”。
  权重从 ModelScope 下载（本机连不上 Hugging Face）到 `data/hy3dgen/tencent/Hunyuan3D-2mv/hunyuan3d-dit-v2-mv/`；
  transformers 必须是 4.48.x（5.x 改了 DINOv2 层名，权重对不上）。
- `tools/render_3d.py`（moderngl 离屏 OpenGL）：**不用 AI 生成贴图**，着色时把原画从正面 / 背面 / 侧面 / 镜像侧面四个方向投影到模型上，
  每个方向先渲深度图做遮挡判断，按表面朝向的 22 次方混合（几乎只取最正对的那张，避免 45° 时出现双脸），加 0.0028 宽的描边。
  自动找“正面朝向”（三张图轮廓一起对，重合度 0.88~0.92），对齐待机动图的身高、脚底和中心，输出 `turn360@2x.webp`（120 帧、50fps、一圈 2.4 秒）。
  渲染时去掉模型最底 1.5% 高度里的面（脚底那片薄板）。注意 OpenGL 读回图像要上下翻转。
- 桌宠：有 `turn360` 时，「转身展示」自动换成三维转身（`turn3d`），**登场 / 召唤动画**换成两倍速三维转一圈并弹出（`show3d`）。
### 2. 动作更顺
- 换动作时 0.22 秒交叉淡入（`Stage._fade`），旧姿势退得慢一点，中间不发虚；开心时的粒子改为从身体两侧飞出，不挡脸。
### 3. 声音：自然、有情绪、可调甜度
- `moepal/cosy_worker.py`（环境 `.conda-voice`）：Fun-CosyVoice3-0.5B（阿里通义，Apache-2.0）。情绪 → 训练时见过的语气指令
  （非常开心 / 非常伤心 / 非常生气 / very soft voice），语气词自动加 `[laughter]` `[sigh]` `[breath]`。
  实测同一句话：开心 364Hz、平静 320Hz、难过 247Hz、害羞 229Hz、生气 407Hz——情绪确实生效。
  但在 Windows 上它的语言模型逐字生成很慢（合成时间约为音频时长的 1.7 倍，没有 vLLM），不适合实时聊天。
- 所以聊天用组合方案：`tools/make_emotion_refs.py` 用 CosyVoice 给每位角色 × 5 个情绪组（开心 / 难过 / 生气 / 轻柔 / 平静）× 3 档甜度
  录好参考音频（`data/voices/<角色>/emo_<组>_s<甜度>.wav`，共 45 段）；聊天时 ZipVoice（约 0.35 倍实时）按这句话的情绪挑参考，
  连语气一起模仿。实测：开心 400Hz、平静 333Hz、难过 242Hz、害羞 239Hz 且明显放慢。这是默认声线「自然有情绪 · 快速」；
  「CosyVoice 原声」保留为可选（最细腻，但每句要等几秒）。
- 甜度：菜单「声音 → 甜度」三档，参考音色整体抬高 0 / 14 / 28 Hz。语速调慢到 0.85~0.9（之前平静时每秒 8 个字，偏快）。
- 用户自己放的 `data/voices/<角色>/prompt.wav` 优先，此时不换情绪参考。
### 4. 小人自己的情绪表达
- 闲时按心情 / 时间偶尔冒一句心里话（只显示、不出声），每人四组台词（开心 / 平静 / 低落 / 深夜）。
### 5. 角色 PV
- `tools/pv_scripts.py`：三支 PV 的分镜与台词（开场 / 初次见面 / 资料卡 / 背景故事 / 性格小剧场 / 桌面上的伙伴 / 和你在一起 / 片尾），
  每句标好情绪。`tools/make_pv.py`：CosyVoice 逐句配音（有缓存）→ 自动排时间轴并拉到 5 分钟 → numpy 合成配乐（各自的音色、
  和弦进行、速度；人声出现时自动压低）→ Qt 逐帧绘制 1080p30（复用桌宠的角色渲染：动作、三维转身、粒子）→ libx264 编码。
  本机 ffmpeg 的 NVENC 用不了（参数错误），改用 CPU 编码，每帧约 33 毫秒，一支约 5~6 分钟。
  成片：`data/pv/<角色>/<角色>_PV.mp4`，复制到桌面素材文件夹 `角色PV\`。
- PV 没有新画的手绘帧：画面由现有动作、三维转身、立绘推拉镜头、字幕和程序绘制的背景组成。

### 验证状态
已验证：三个角色的三维网格与转身渲染（看过各角度截图，45° 无双脸、脚底无残片）；CosyVoice 与“快速有情绪”两条语音路线的音高 / 语速对比；
PV 30 秒预览逐帧截图检查；三支完整 PV 已渲染并逐段抽帧检查（均为 300.0 秒、1920×1080、30fps、AAC 立体声，约 110~135MB，在桌面 `AI动漫助手_角色素材\角色PV\`）；三维登场动画离屏逐帧检查（弹出的同时完整转一圈）。
补记：三维转身用到的帧若后台还没解出，`Clip.pair` 现在当场解码（加锁），否则离线渲染和两倍速登场会停在正面。
未验证：**声音好不好听、甜度合不合适**（我听不到）；PV 的整体观感和节奏需要你看；在真实窗口上的三维登场动画；麦克风、真实鼠标手势同前。
已知局限：三维模型是从三张图推出来的，斜角度的贴图来自相邻两张原画，细节（尤其侧脸）不如正面精致；三维只用于转身 / 登场，其余动作仍是二维序列帧。

## 2026-11-19 · v0.4 RIFE 重新补帧、显卡语音（参考音色）、两个 Agent 都可选任意模型

用户反馈：动作还是不流畅；声音僵硬不丝滑，希望去网上找符合角色的声音来调；大小姐接 Claude Code 且能选任何 Claude 模型，白龙娘接 Codex。

### 先量再改
- `tools/fps_probe.py`：在真实窗口上量重绘。结果：稳定 125 次/秒、零掉帧、每帧 1 毫秒——**程序渲染不是瓶颈**。
- 量素材本身相邻帧的变化：旧的“流畅动画”每 12 帧（= 每张关键帧）有一次明显跳变，跳跃动作相邻帧差异中位数高达 36（待机是 2.8）。
  **卡顿的根因是素材**：8 张关键帧之间的光流补帧质量差，到关键帧处“一顿”。

### 改动
1. **RIFE 补帧**（`tools/interp_assets.py`）：从桌面素材的关键帧重新生成——Real-ESRGAN 放大 2 倍 → rife-ncnn-vulkan（nihui 官方发布，rife-v4.6，用显卡）补到 50fps，
   首尾相接无缝循环；RGB 与透明通道分两路补帧再合并。每个动作按快慢设关键帧间隔（待机 0.55 秒、跳跃 0.28 秒）。旧文件移到 `assets/_old/`。
   待机：相邻帧差异中位数 2.84 → 1.80，循环接缝 7.43 → 1.24。
2. **按真实时间轴播放**：WebP 编码器会把完全相同的连续帧合并成一张长帧（例：待机里一段 480ms 的停顿）。
   补帧工具把每帧时长写进同名 `.json`，`stage.Clip.at(ms)` 按时间轴取帧，长帧只在最后 20ms 才过渡到下一帧。
   （v0.3 的 `Clip` 读 `duration` 时没先 `load()`，一直是默认值 40ms——旧素材恰好是 40ms 所以没暴露。）
3. **显卡语音**（`moepal/tts_worker.py` + `voice.ZipVoiceClient`）：ZipVoice（k2-fsa，用 10 万小时真实口语训练的零样本 TTS）+ Vocos 声码器，
   跑在独立子进程里，CUDA 优先、不行退 CPU。每个角色一段**参考音色** `data/voices/<角色>/prompt.wav` + `prompt.txt`：
   默认用微软合成声线念一段口语化的话生成（小白：晓伊、大小姐：晓晓、小鲸：晓伊 +18Hz）；**没有用任何真人配音演员的录音**。
   用户可以换成自己有权使用的 5~10 秒干净录音。实测 RTX 5070 Ti：一句 4 秒的话合成约 1.5~2 秒；首次在新显卡上运行要约 90 秒预热，之后有缓存。
   语音进程启动和每次换角色时会后台预热。ZipVoice 失败时自动用同一参考声线的在线版本顶上。它是每个角色声线列表的第一项（默认）。
   sherpa-onnx 换成 CUDA 版（`2.0.1+cuda12.cudnn9`，仍可跑 CPU）+ NVIDIA 官方 `nvidia-cudnn-cu12`；CUDA 运行库用本机已装的 CUDA 12.9。
4. **模型菜单**：大小姐「模型（Claude Code）」= 跟随 Claude Code 默认 / Haiku / Sonnet / Opus / Fable + 输入任意完整模型名；
   白龙娘「模型（Codex）」= 跟随 Codex 默认 + Codex 应用缓存里的全部可用模型（`~/.codex/models_cache.json`）+ 输入任意名称。
   别名永远指向该系列最新版。`find_codex` 取 `%LOCALAPPDATA%\OpenAI\Codex\bin\*\codex.exe` 里最新的那个。

### 验证状态
已验证：Codex、Claude Code 两个后端真实回复（`smoke_test.py --net`）；真实窗口重绘 125 次/秒零掉帧；三个角色的显卡语音经子进程真实合成（cuda）；RIFE 补帧前后的相邻帧差异对比。
未验证：**声音好不好听我听不到**——客观上 ZipVoice 的语速更接近说话（同一句 7.7 秒 vs 在线 10.2 秒），音高起伏略大，但“自然”需要你听；
补帧后的动作在真实窗口上的观感；DeepSeek 用 v1 的 4 张关键帧补帧，姿势差别大，可能有变形；麦克风、真实鼠标手势同前。

## 2026-11-16 · v0.3 真正的高帧率、连贯语音、角色档案、Claude 模型可选

用户反馈：动画还是不流畅、帧率太低；声音还是奇怪，要连贯自然；希望有背景故事和其他视角图；
Claude 大小姐要能选 Opus / Fable 等模型。

### 根因与改动
1. **帧率**。查到三个原因：
   - 用户屏幕是 **240Hz**，v0.2 按 60fps 画，在高刷屏上本身就发顿 → 渲染帧率改为 min(屏幕刷新率, 120)，取刷新率的整数分之一（240Hz 屏 = 120fps），用电池时减半。
   - 素材只有 25fps → `Clip.pair()` 返回相邻两帧和比例，`Stage._mix()` 在两帧间线性混合，每次刷新画面都不同（实测 120 张/秒，之前约 25）。素材已是光流补帧，相邻帧差别小，混合不出重影；v1 的 4 帧素材不混合。
   - 界面线程自己解码、彩色 emoji 粒子每帧 drawText → 偶发几十到上百毫秒的卡顿。解码改到后台线程并预读 6 帧；粒子字形预渲染成图片缓存；启动时预载每段动图首帧。
   实测每帧平均 1.1ms、95 分位 1.7ms（v0.2：平均 4.2ms、95 分位 10.6ms，粒子多时 23ms）。
2. **语音**。v0.2 把每个短句拆开单独合成并各给一个音高，结果一顿一顿、忽高忽低，更不自然。
   新增 `plan_flow`（默认）：整段交给引擎一口气念，只在整句边界且超过约 48 字时才切，全程同一音高；候选声线的基准变调全部归零。
   说话时不再叠情绪提示音；提示音默认音量 0.55 → 0.3，可在菜单关掉。菜单里可切回“逐句起伏”。
   新增本地声线 MeloTTS 中文女声（sherpa-onnx VITS，约 170MB，一句约 0.5 秒）。
3. **角色档案**。`tools/make_views.py` 从三视图抠出正面 / 侧面 / 背面透明立绘（只去掉与图片边缘连通的近白色，身上的白色不受影响）并导入常规比例立绘。
   `ProfileWindow`：左侧可切换四个视角，右侧资料表 + 背景故事。三位角色各写了背景故事和 9 项资料（`characters.py` 的 `story` / `profile` / `tagline`），
   并写进给模型的人设，聊到来历时她答得上来。
4. **三视图动作**：`ACTIONS` 的素材项可以是随时间换图的函数。新增「转身展示」（正→侧→背→另一侧→正，换面瞬间横向压扁模拟转身）、「背过身去」（被戳生气后会用）、「侧身远望」。共 57 个动作。
5. **Claude 模型可选**：菜单「模型（Claude）」：Haiku 5.5 / Sonnet 5.5 / Opus 5.5 / Fable 5.2，存到 `claude_model`，菜单标题栏显示当前模型。四个别名都实测能回复（5–6 秒）。

### 验证状态
已验证：帧耗时与每秒不同画面数（脚本实测，见上）；`smoke_test.py`；离屏渲染看过档案窗口和转身动作；MeloTTS / 连贯模式能合成；四个 Claude 模型别名真实回复。
未验证：**我听不到声音**，连贯模式是否“自然”仍需用户判断；在真实窗口上的观感（用户当时在全屏游戏，未开窗测试）；
麦克风、真实鼠标手势同前。

## 2026-11-16 · v0.2 流畅度、清晰度、界面、声音、各接各的 Agent

用户反馈：动画帧率低不流畅；角色边缘模糊；菜单和小窗口不够美观；声音“AI 味”重、没有抑扬顿挫；
希望白龙娘接 Codex、Claude 大小姐接 Claude Code（DeepSeek 没装，先不接）。

### 改动
1. **流畅度**：v0.1 为省内存每 3 帧取 1（约 8fps）并以 30fps 刷新。现在 `stage.Clip` 改成**流式解码**——播到哪帧解哪帧，
   内存只占一两帧，于是用上全部 25fps 原帧；窗口刷新改 60fps（`PreciseTimer` 16ms），程序化运动和粒子按 60fps 走。
   实测（2x 素材、同时有超分任务占 CPU）每个显示帧平均 4.2ms，95 分位 10.6ms。
2. **清晰度**：边缘发虚的根因是素材只有 288×416。`tools/upscale_assets.py` 用 Real-ESRGAN animevideov3（SRVGGNetCompact，
   CPU 版 PyTorch）把每一帧放大：RGB 先做颜色外扩再过网络；alpha 通道单独过同一个网络得到锐利轮廓并收紧过渡带；
   4x 输出 Lanczos 缩到 2x，存成 `<clip>@2x.webp`（576×832）。`ClipBank` 优先读 @2x。
3. **界面**（`widgets.py` 重写）：跟随系统深/浅色；强调色取当前角色；气泡、输入栏带柔和阴影和淡入淡出；
   麦克风/发送改为矢量图标；等待回复时气泡里三个跳动的点；菜单改为圆角半透明、带角色名和所接 Agent 的标题栏，
   去掉 emoji，动作表演按“情绪 / 日常 / 表演”分组。
4. **声音**（新增 `voice.py`）：一段话拆成短句，逐句给不同语速/音高/音量和停顿（感叹更快更高、疑问上扬、省略号拖慢留白、
   语气词单独成句、首句略高末句略低、每句带随机起伏），并行合成、顺序播放，气泡文字跟着每一句的声音出现。
   去掉了原来 +18Hz/+32Hz 的整体变调。每个角色有一组候选声线，菜单「声音 → 声线」点一下即试听并选用：
   4 个微软在线神经声线 + 7 个本地 Kokoro v1.1 中文女声（sherpa-onnx，离线，模型约 380MB 在 `data/models/`）。
   对话规则里加了“像说话不像写作”的要求。在线合成并发时偶尔回空音频 → 加了重试。
5. **各接各的 Agent**：白龙娘 → **Codex**（`find_codex` 改为优先用 Codex 桌面应用自带的 codex.exe，0.167；PATH 里那个 0.140 太旧）；
   Claude 大小姐 → **Claude Code**；不再互相降级。大肥鱼未接 DeepSeek，暂由 Claude 代答并在菜单标题里写明。
6. **有自己的想法**：回复协议增加可选的 `[think:…]` 心里话，显示在气泡正文上方（灰色斜体，不念出来）。
7. **新动作 16 个**（共 54 个）：灵光一闪、用力点头、摇头、小鹿乱撞、打喷嚏、踮脚张望、踩点小舞、喝咖啡、陪你学习、鼓掌、
   头顶乌云（带雨滴）、雨过天晴、专属飘落、专注燃烧、太空步、敬礼。心情低落时会自己顶乌云，回暖后放晴；
   你在写代码/看课件时闲时动作偏向“陪你学习”“专注”。
8. **不打扰全屏**：前台是全屏程序（游戏、全屏视频）时桌宠整个隐藏、不出声，退出全屏再出现。
9. `tools/render_ui.py`：不上屏、不出声地把界面渲染成图，供开发时检查。

### 验证状态
已验证：`smoke_test.py --net` 全过（含 **Codex 后端真实回复**、Claude 后端、54 个动作、全部 @2x 帧可解码）；
离屏渲染图看过深/浅色的气泡、输入栏、菜单、角色；逐句语音在一次真实联调里按句播放、文字对齐。

未验证：
- **声音好不好听我无法判断**（我听不到音频）。默认声线是按微软给的风格标签选的，需要你在菜单里逐个试听后定。
- 真实鼠标手势、麦克风识别仍未实测（同 v0.1）。
- 新的 16 个动作没有重新导出成 GIF（桌面 `情绪动作_v3_组合动作` 里仍是 v0.1 的 35 个、1x 清晰度）。
- 全屏自动隐藏只按“前台窗口铺满主屏”判断，未在各种游戏上实测。

## 2026-11-15 · v0.1 首版

### 本次完成
1. **动画补全**
   - `tools/import_assets.py` 把 v2（缺的用 v1）导入 `assets/<角色>/<动作>.webp`。
   - `moepal/stage.py`：18 种程序化运动（呼吸、弹跳、摇摆、发抖、旋转眩晕、歪头、挤压回弹、伸展、登场弹出、漂浮、转圈、后空翻、行走…）
     + 粒子（爱心、星星、音符、Zzz、汗、泪、💢、❗、❔、💫 及角色专属 ✨🔥 / 🌸📖 / 🫧🐳），组合成 **38 个动作**。
   - DeepSeek 缺的 待机/翻书/哼歌/专属互动 用其他序列帧 + 程序化运动替代（`Character.fallback`）。
   - `tools/export_actions.py` 把其中 35 个导出为透明 WebP + GIF → 桌面素材文件夹 `情绪动作_v3_组合动作\`（3 角色 × 35 × 2 = 210 个动图）。
2. **角色音频轨道**（`moepal/sfx.py`，全部程序合成，无采样）
   - 白龙娘 crystal：非谐泛音水晶铃 + 小龙“啾/嗷”滑音 + 龙焰气息。
   - 大小姐 musicbox：八音盒拨弦 + 翻书声 + 合书“啪”。
   - 大肥鱼 bubble：上滑音高的水泡“啵”+ 鲸歌滑音 + 声呐。
   - 每人 19 个事件音（问候/登场/退场/戳/摸/开心/打气/难过/惊讶/思考/提醒/入睡/醒来/生气/开始听/结束听/发送/出错/落地）
     + 晕眩 + 呼噜 + 8 个咿呀语音节，共 29 × 3 = 87 个 wav，首次启动生成到 `data/cache/sfx/`。
   - 说话：edge-tts 在线嗓音（小白 Xiaoyi 偏高偏快、大小姐 Xiaoxiao 偏稳、小鲸 Xiaoyi 更高更软），语速/音高随情绪浮动；
     断网或合成失败自动降级为咿呀语；也可选静音。输出跟随系统默认输出设备（插拔耳机自动切换）。
3. **鼠标互动**：慢慢靠近→歪头；高速冲过来→吓一跳；在头上来回蹭→摸头（爱心 + 呼噜 + 好感上升）；旁边疯狂晃鼠标→晕；
   盯着不动 7 秒→害羞；单击→戳（4 秒内戳 5 次→生气）；拖动→被拎起来甩动，松手→落地回弹；滚轮→缩放；身体始终朝鼠标微微倾斜。
4. **桌面感知与主动反应**（`deskctx.py` + `pet.desk_tick`）：前台应用分类（代码/学习/视频/游戏/聊天/浏览）切换后评论一句；
   连续使用 50 分钟提醒休息；0–5 点担心熬夜；CPU 持续 >88% 、电量 ≤20% 提醒；空闲 4 分钟打瞌睡，回来惊醒；
   前台全屏时不打扰；闲时自己哼歌、看书、伸懒腰、散步。
5. **情绪系统**：愉悦 v、精力 e、好感 a 三个数值，受互动、对话情绪、时间影响并缓慢回归；影响待机姿态、语音语调，并写进给模型的 prompt。
6. **对话**：双击或 Ctrl+Alt+M 打开输入栏；🎤 麦克风录音（说完停 1.2 秒自动结束）→ faster-whisper 本地识别；
   模型回复第一行 `[emo:x]` 驱动表情。每天第一次开聊会问“今天要做什么”，记进记忆并带进之后的每次对话。
7. **模型接入**（`brain.py`）：`claude_cli`（复用本机 Claude Code 登录）、`codex_cli`（复用本机 Codex/ChatGPT 登录）、`deepseek_api`。
   每个角色有优先级列表，失败自动降级并提示一次。
8. **隐藏/召唤**：躲到屏幕右边探头偷看（点一下回来）；完全隐藏；托盘图标；全局热键 Ctrl+Alt+M。
9. **Claude Code 主题 mod**（`claude-mod/ojousama-study`）：暖棕书房配色 + Claude 大小姐背景图；会话开始时弹提示并启动桌宠（Claude 大小姐）。
10. 图标（三角色代表色圆环 + 小白头像）、桌面快捷方式「MoePal 萌伴」。
